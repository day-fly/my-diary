# 마음의 가장자리

GitHub로 관리하는 개인 글 아카이브 템플릿입니다.  
시, 에세이, 일상 메모를 마크다운으로 작성하고 사진과 함께 발행할 수 있습니다.

## 포함된 기능

- 최근 글·작성자 프로필·글 검색가 있는 홈
- 종이와 녹색 계열의 차분한 디자인, 읽기 편한 본문
- 모바일에서 고정되는 글쓰기 작업 버튼, 작은 화면 대응
- `/write` 웹 작성 UI (글 작성/수정/삭제 + 사진 업로드)
- 본문 입력창에서 `Ctrl/Cmd + V` 이미지 붙여넣기 업로드
- 글 자동 임시저장과 복원, 서식 버튼, 작성/미리보기 전환
- 이름·한 줄 소개·자기소개·사진·웹사이트 프로필 편집
- 마크다운 포스트 작성
- GitHub Pages 배포용 워크플로

## 폴더 구조

```text
.
├─ _posts/                # 글 포스트 (YYYY-MM-DD-title.md)
├─ _layouts/              # 공통 레이아웃
├─ assets/
│  ├─ css/style.css       # 스타일
│  ├─ images/             # 대표 이미지/일러스트
│  └─ photos/             # 직접 올릴 사진 폴더
├─ index.html             # 홈
├─ write.md               # 웹 작성 UI
├─ oauth-proxy/           # OAuth token 교환 Worker
├─ about.md               # 소개 페이지
└─ _config.yml            # Jekyll 설정
```

## 화면에서 쓰고 관리하기

- **글꼴**: 제목·본문·소개 글·글쓰기 본문은 마루부리, 메뉴·버튼·검색 등 조작 요소는 프리텐다드입니다. 마루부리는 네이버의 WOFF2 원본을 함께 배포하고, 프리텐다드는 공식 v1.3.9 가변 서브셋 웹폰트로 필요한 글자만 불러옵니다. 출처와 라이선스는 `assets/fonts/CREDITS.txt`와 `assets/fonts/maruburi/LICENSE.txt`에 보관합니다.
- **글별 삽화**: 2026-11-07 기준 사진이 없던 글 39편에 본문을 읽고 만든 수채화·연필화 분위기의 삽화를 한 장씩 연결했습니다. 글 상단과 목록 표지는 같은 그림을 사용하며, 모바일에서는 작은 파일을 골라 불러옵니다. 이미지 설명은 `_data/illustrations.json`에서 관리합니다. 글쓰기에서 다른 표지를 선택하면 그 표지가 우선하고, 새 글에 그림이 자동으로 생성되지는 않습니다.
- **배경음악**: Kevin MacLeod의 *Touching Moments One - Pulse*를 기본 20% 음량으로 자동 재생 시도합니다. 브라우저가 자동 재생을 막으면 재생 버튼으로 시작합니다. 직접 끈 설정과 음량은 다음 방문에도 기억하며, 재생 위치는 현재 탭에서 이어집니다. 모바일에서 아래로 스크롤하면 작은 음악 아이콘으로 접히고 눌러 재생·정지·음량을 조절합니다. 곡 정보와 CC BY 4.0 출처는 플레이어 및 `assets/audio/CREDITS.txt`에 있습니다.
- **계절 테마**: 한국 시간(Asia/Seoul) 기준 봄 3–5월, 여름 6–8월, 가을 9–11월, 겨울 12–2월에 따라 색과 문구가 바뀝니다. 화면 전체에 봄 꽃잎·여름 초록 잎·가을 낙엽·겨울 눈이 은은하게 흩날립니다. 모바일에서는 효과 수와 크기를 줄입니다. 하단 또는 음악 설정의 **계절 효과 끄기**로 중지할 수 있고 선택을 기억합니다. 기기의 동작 줄이기 설정에서는 효과를 끄며, 보이지 않는 탭에서는 일시정지합니다. 계절은 한국의 자정과 화면에 돌아올 때 갱신됩니다.
- **글쓰기**: 제목과 본문만 입력해도 브라우저에 자동 임시저장됩니다. `Ctrl/Cmd + S` 또는 **임시저장**으로도 저장할 수 있습니다. 임시글은 현재 브라우저와 저장소별로 한 편을 유지하며, 다른 기기에 동기화되지 않습니다. 공용 기기에서는 주의해 주세요.
- **읽기**: 본문 기본 크기는 17px이며 **가− / 가+**로 16–22px 사이에서 조절하고 다음 글에서도 유지합니다. 시의 원래 문단과 줄바꿈은 보존합니다. 글 아래의 **함께 읽으면 좋은 글**은 제목과 본문 단어의 유사도로 자동 선택하므로 별도 분류나 태그 입력이 필요 없습니다.
- **미리보기**: 작성/미리보기 버튼으로 전환합니다. 기본 마크다운 서식과 사진을 확인할 수 있으며 복잡한 Kramdown 문법은 실제 발행 결과와 차이가 있을 수 있습니다.
- **표지**: 별도 표지가 없으면 본문 첫 사진을 목록과 최신 글의 표지로 사용합니다. 글쓰기의 **사진 추가**에서 표지 업로드·주소 지정·자동 선택 해제·표지 없이 표시를 선택할 수 있습니다. 업로드한 표지는 긴 변 1,600px 이내의 JPG로 저장하며 작은 이미지는 확대하지 않습니다. 목록은 4:3 비율로 가운데를 잘라 표시하고 본문 원본은 그대로 유지합니다. GIF 표지는 정지 이미지로, 투명한 부분은 흰색으로 저장됩니다. 기존 글의 자동 표지는 원본 주소를 재사용하고 화면에 보일 때 불러옵니다.
- **사진**: 표지 또는 본문 사진을 선택합니다. JPG/PNG/WebP/GIF, 한 장당 10MB 이하를 지원합니다. 파일 선택은 브라우저에 보관되지 않으므로 새로고침 후 다시 선택해야 합니다. 붙여넣기는 연결된 계정으로 즉시 업로드합니다.
- **발행**: 최초 한 번 **발행 계정 연결**에서 기존 OAuth 설정이나 GitHub 토큰을 입력합니다. 저장소 주소는 미리 채워집니다. 기본 로그인 정보는 현재 탭 세션에만 유지하고, **이 기기에 로그인 정보 기억하기**를 선택한 경우에만 장기 저장합니다. 발행 완료 후 Pages 배포까지 시간이 걸릴 수 있습니다. 미래 날짜 예약 발행은 지원하지 않습니다.
- **수정**: 글 하단의 **이 글 수정**, 또는 글쓰기의 **기존 글 수정**에서 제목으로 선택합니다. 다른 곳에서 수정한 글은 덮어쓰지 않고 다시 불러오도록 안내합니다.
- **프로필**: **소개 → 프로필 편집**, 또는 **글쓰기 → 내 프로필**에서 사진·이름·소개를 입력하고 **프로필 저장**을 누릅니다. `_data/profile.json`에 저장되어 모든 방문자에게 공개됩니다. 사진 지우기는 프로필에서 사진을 빼며 기존 업로드 파일을 삭제하지 않습니다. 프로필 편집 내용은 저장 버튼으로 발행해야 합니다.
- **검색**: 홈과 `/archive/`에서 제목·본문으로 검색합니다. 홈의 **모든 글 보기**를 누르면 목록으로 바로 이동합니다. 글쓰기와 목록에 분류 선택·표시는 없으며, 기존 글에 저장된 과거 분류 값은 수정 시 다른 추가 정보와 함께 보존합니다.

## 새 글 작성 방법

### 가장 쉬운 방법: 웹 UI에서 작성/발행

`/write` 페이지에서 제목/본문/사진 입력 후 `발행하기`를 누르면:

- `assets/photos/`에 이미지 업로드
- `_posts/`에 포스트 파일 생성
- GitHub에 바로 커밋

`기존 글 수정` 섹션에서는:

- `_posts` 목록 조회
- 선택 글 불러오기(수정 모드)
- 현재 글 삭제

본문 입력창에 이미지를 붙여넣으면:

- 자동으로 `assets/photos/` 경로에 업로드
- 업로드된 이미지 Markdown이 커서 위치에 자동 삽입

#### 1) 작성 페이지 열기

- 로컬: `http://127.0.0.1:4001/my-diary/write/`
- 배포 후: `https://day-fly.github.io/my-diary/write/`

#### 2) OAuth 로그인 방식 (토큰 입력 없음)

`oauth-proxy` 폴더의 Worker를 먼저 배포해야 합니다.

- 가이드: `oauth-proxy/README.md`
- 필요한 값:
  - OAuth Client ID (GitHub OAuth App)
  - OAuth Proxy URL (Cloudflare Worker 배포 URL)

`/write` 페이지에서 두 값을 입력하고 `GitHub로 로그인` 버튼을 누르면
토큰이 자동으로 연결됩니다.

배포 명령 예시:

```bash
cd oauth-proxy
npx wrangler secret put GITHUB_CLIENT_SECRET
npx wrangler deploy
```

#### 3) 수동 토큰 방식 (백업)

GitHub에서 Fine-grained personal access token을 만들고 아래 권한을 주세요.

- Repository access: 이 저장소 선택
- Repository permissions: `Contents` → `Read and write`

#### 4) 연결 정보 입력

- Owner: GitHub 사용자명
- Repo: 저장소 이름
- Branch: 보통 `main`
- Token: OAuth 자동 입력 또는 수동 토큰 입력

토큰 저장 체크를 켜면 현재 브라우저에만 저장됩니다.

### 추천: 자동 생성 스크립트 사용

수작업 대신 아래 명령으로 글 뼈대를 바로 만들 수 있습니다.

```bash
./scripts/new-post.sh "일요일의 기록" "/절대경로/사진.jpg"
```

또는 대화형 입력:

```bash
./scripts/new-post.sh
```

실행하면 자동으로:

- `_posts/`에 날짜 기반 파일 생성
- (사진 입력 시) `assets/photos/`로 사진 복사
- `title`, `date`, `cover`, 본문 템플릿 자동 작성

### 수동 작성 방식

1. `_posts/` 안에 파일 생성  
   예: `_posts/2026-03-01-sunday-note.md`
2. 아래 형식으로 프론트매터 작성

```md
---
title: "일요일의 기록"

date: 2026-03-01 21:30:00 +0900
cover: /assets/photos/2026-03-01-coffee.jpg
---

오늘의 기록을 자유롭게 씁니다.

![카페 사진](/assets/photos/2026-03-01-coffee.jpg)
```

3. 사진은 `assets/photos/` 폴더에 업로드
4. Git 커밋 후 GitHub에 푸시

## GitHub Pages 배포

이 저장소에는 `.github/workflows/pages.yml`이 포함되어 있어서,  
`main` 브랜치에 푸시하면 Pages가 자동 배포됩니다.

### GitHub에서 1회 설정

1. Repository `Settings` → `Pages`
2. `Build and deployment` 에서 `Source` 를 `GitHub Actions` 로 선택

이후 푸시할 때마다 자동 배포됩니다.

## 로컬 미리보기 (선택)

Ruby/Jekyll 환경이 있으면 로컬에서도 확인할 수 있습니다.

```bash
bundle install
bundle exec jekyll serve --host 127.0.0.1 --port 4001
```

브라우저에서 `http://127.0.0.1:4001/my-diary/` 접속.
