# 마음의 가장자리

GitHub로 관리하는 개인 글 아카이브 템플릿입니다.  
시, 에세이, 일상 메모를 마크다운으로 작성하고 사진과 함께 발행할 수 있습니다.

## 포함된 기능

- 최근 글·작성자 프로필·글 검색가 있는 홈
- 종이와 녹색 계열의 차분한 디자인, 읽기 편한 본문
- 모바일에서 고정되는 글쓰기 작업 버튼, 작은 화면 대응
- `/write` 웹 작성 UI (글 작성/수정/삭제 + 사진 업로드)
- 본문 입력창에서 `Ctrl/Cmd + V` 이미지 붙여넣기 업로드
- 브라우저 자동 임시저장, 사진을 포함한 비공개 보관함, 기기 간 이어 쓰기
- 공개·비공개·임시글 검색 및 관리, 실제 사이트 반영 상태 확인
- 날짜에서 자동 생성되는 연도별 기록 탐색, 서식 버튼, 작성/미리보기 전환
- 이름·한 줄 소개·자기소개·사진·웹사이트 프로필 편집
- 마크다운 포스트 작성
- GitHub Pages 배포용 워크플로

## 폴더 구조

```text
.
├─ _posts/                # 글 포스트 (YYYY-MM-DD-title.md)
├─ _layouts/              # 공통 레이아웃
├─ assets/
│  ├─ css/style.css       # 스타일
│  ├─ images/             # 대표 이미지/일러스트
│  └─ photos/             # 직접 올릴 사진 폴더
├─ index.html             # 홈
├─ write.md               # 웹 작성 UI
├─ oauth-proxy/           # OAuth token 교환 Worker
├─ about.md               # 소개 페이지
└─ _config.yml            # Jekyll 설정
```

## 화면에서 쓰고 관리하기

- **글꼴**: 제목·본문·소개 글·글쓰기 본문은 마루부리, 메뉴·버튼·검색 등 조작 요소는 프리텐다드입니다. 마루부리는 네이버의 WOFF2 원본을 함께 배포하고, 프리텐다드는 공식 v1.3.9 가변 서브셋 웹폰트로 필요한 글자만 불러옵니다. 출처와 라이선스는 `assets/fonts/CREDITS.txt`와 `assets/fonts/maruburi/LICENSE.txt`에 보관합니다.
- **글별 삽화**: 2026-11-07 기준 사진이 없던 글 39편에 본문을 읽고 만든 수채화·연필화 분위기의 삽화를 한 장씩 연결했습니다. 글 상단과 목록 표지는 같은 그림을 사용하며, 모바일에서는 작은 파일을 골라 불러옵니다. 이미지 설명은 `_data/illustrations.json`에서 관리합니다. 글쓰기에서 다른 표지를 선택하면 그 표지가 우선하고, 새 글에 그림이 자동으로 생성되지는 않습니다.
- **배경음악**: 피아노·하프·어쿠스틱 기타 중심의 Kevin MacLeod 연주곡 6곡을 기본 20% 음량으로 이어 듣습니다. 기본은 **섞어 듣기**이며, 한 바퀴 돌기 전에는 같은 곡을 반복하지 않습니다. 플레이어를 펼쳐 이전·다음 곡 이동, 직접 곡 선택, 섞어 듣기 전환을 할 수 있습니다. 페이지를 옮겨도 현재 탭에서 곡·재생 위치·순서를 이어가고, 새 방문의 첫 곡은 직전 곡과 다르게 고릅니다. 직접 끈 설정과 음량은 계속 기억하며, 끈 상태에서 곡만 바꿔도 재생하거나 파일을 내려받지 않습니다. 브라우저가 자동 재생을 막으면 재생 버튼으로 시작합니다. 모바일에서 아래로 스크롤하면 작은 음악 아이콘으로 접힙니다. 곡 목록은 `_data/music.json`, 곡별 원본과 CC BY 4.0 출처는 플레이어 및 `assets/audio/CREDITS.txt`에 있습니다.
- **계절 테마**: 한국 시간(Asia/Seoul) 기준 봄 3–5월, 여름 6–8월, 가을 9–11월, 겨울 12–2월에 따라 색과 문구가 바뀝니다. 화면 전체에 봄 꽃잎·여름 초록 잎·가을 낙엽·겨울 눈이 은은하게 흩날립니다. 모바일에서는 효과 수와 크기를 줄입니다. 하단 또는 음악 설정의 **계절 효과 끄기**로 중지할 수 있고 선택을 기억합니다. 기기의 동작 줄이기 설정에서는 효과를 끄며, 보이지 않는 탭에서는 일시정지합니다. 계절은 한국의 자정과 화면에 돌아올 때 갱신됩니다.
- **작성자 로그인**: 방문자에게는 **로그인**만 보이며, GitHub에서 `_config.yml`의 `writer.owner` 계정과 저장소 수정 권한을 확인한 뒤 **글쓰기**, **이 글 수정**, **프로필 편집**을 표시합니다. `/write/`에 직접 들어와도 로그인 전에는 작성 화면과 임시글을 열지 않습니다. 기존 GitHub 토큰·세션·간편 로그인 설정을 재사용하며, 토큰 문자열이나 저장된 로그인 표시만으로는 메뉴를 열지 않습니다. 로그아웃하면 두 저장 공간의 로그인 정보를 지우고 다른 탭에도 알립니다. 비공개·보관함 글의 현재 탭 사본도 지우며 비공개 보관함에 저장한 원본은 유지합니다. 정적 사이트이므로 이 기능은 작성자 UI를 제어하며, 실제 저장·삭제 권한은 GitHub API가 검사합니다.
- **글쓰기·보관함**: 입력 중인 한 편은 브라우저에 자동 임시저장됩니다. **보관함 저장** 또는 `Ctrl/Cmd + S`를 누르면 제목·본문·표지·사진을 비공개 저장소의 `_diary_drafts/`에 저장합니다. 여러 임시글을 보관하고 다른 기기에서 로그인해 **임시글 보관함 → 이어 쓰기**로 열 수 있습니다. 글을 새로 쓰면 별도 임시글로 저장하며, **새 임시글로 보관**은 원본과 독립된 사본을 만듭니다. 다른 기기에서 수정한 글은 덮어쓰지 않습니다. 발행에 성공하면 해당 버전의 임시글만 정리하며, 정리에 실패하면 보관함에 남았다고 안내합니다. 보관함 저장 전의 파일 선택·붙여넣기 사진은 새로고침하면 사라질 수 있습니다.
- **읽기**: 본문 기본 크기는 17px이며 **가− / 가+**로 16–22px 사이에서 조절하고 다음 글에서도 유지합니다. 시의 원래 문단과 줄바꿈은 보존합니다. 글 아래의 **함께 읽으면 좋은 글**은 제목과 본문 단어의 유사도로 자동 선택하므로 별도 분류나 태그 입력이 필요 없습니다.
- **미리보기**: 작성/미리보기 버튼으로 전환합니다. 기본 마크다운 서식과 사진을 확인할 수 있으며 복잡한 Kramdown 문법은 실제 발행 결과와 차이가 있을 수 있습니다.
- **표지**: 별도 표지가 없으면 본문 첫 사진을 목록과 최신 글의 표지로 사용합니다. 글쓰기의 **사진 추가**에서 표지 업로드·주소 지정·자동 선택 해제·표지 없이 표시를 선택할 수 있습니다. 업로드한 표지는 긴 변 1,600px 이내의 JPG로 저장하며 작은 이미지는 확대하지 않습니다. 목록은 4:3 비율로 가운데를 잘라 표시하고 본문 원본은 그대로 유지합니다. GIF 표지는 정지 이미지로, 투명한 부분은 흰색으로 저장됩니다. 기존 글의 자동 표지는 원본 주소를 재사용하고 화면에 보일 때 불러옵니다.
- **사진**: 표지 또는 본문 사진을 선택합니다. JPG/PNG/WebP/GIF, 한 장당 10MB 이하를 지원합니다. 선택·붙여넣기한 사진은 저장 전까지 브라우저 메모리에 보관합니다. **보관함 저장**을 누르면 비공개로 저장되어 새로고침하거나 다른 기기에서 열어도 복원됩니다. 발행할 때는 선택한 공개 범위의 저장 공간으로 옮깁니다.
- **발행**: 상단 **로그인 → 작성자 계정**에서 기존 발행용 GitHub 토큰으로 로그인합니다. 기존 OAuth 연결이 있다면 **GitHub로 로그인**도 사용할 수 있습니다. 기본 로그인 정보는 현재 탭 세션에만 유지하고, **이 기기에 로그인 정보 기억하기**를 선택한 경우에만 장기 저장합니다. **저장됨 → 사이트 반영 중 → 반영 완료**로 진행 상황을 표시합니다. 실제 배포된 `publication-status.json`의 글 버전으로 확인하며, 비공개 전환·삭제는 해당 변경을 포함한 배포에서 공개 글이 사라졌는지도 확인합니다. 확인이 늦거나 연결에 실패하면 완료로 표시하지 않고 **다시 확인**을 제공합니다. 상태 확인은 현재 탭에서 이어집니다. 미래 날짜 예약 발행은 지원하지 않습니다.
- **수정**: 글 하단의 **이 글 수정**, 또는 글쓰기의 **글 관리**에서 제목을 검색하고 **공개·비공개·임시글**로 걸러 찾습니다. 각 행에서 수정·이어 쓰기·공개 범위 전환을 할 수 있습니다. 다른 곳에서 수정한 글은 덮어쓰지 않고 다시 불러오도록 안내합니다.
- **프로필**: **소개 → 프로필 편집**, 또는 **글쓰기 → 내 프로필**에서 사진·이름·소개를 입력하고 **프로필 저장**을 누릅니다. `_data/profile.json`에 저장되어 모든 방문자에게 공개됩니다. 사진 지우기는 프로필에서 사진을 빼며 기존 업로드 파일을 삭제하지 않습니다. 프로필 편집 내용은 저장 버튼으로 발행해야 합니다.
- **검색**: 홈과 `/archive/`에서 제목·본문으로 검색하고 연도별로 좁혀 볼 수 있습니다. 연도는 글 날짜에서 자동 생성되며 검색과 함께 적용됩니다. 선택한 연도·검색어는 주소에 반영되어 공유하거나 뒤로 가기로 복원할 수 있습니다. 홈의 **모든 글 보기**를 누르면 목록으로 바로 이동합니다. 글쓰기와 목록에 분류 선택·표시는 없으며, 기존 글에 저장된 과거 분류 값은 수정 시 다른 추가 정보와 함께 보존합니다.

## 새 글 작성 방법

### 가장 쉬운 방법: 웹 UI에서 작성/발행

`/write` 페이지에서 제목/본문/사진 입력 후 `발행하기`를 누르면:

- `assets/photos/`에 이미지 업로드
- `_posts/`에 포스트 파일 생성
- GitHub에 바로 커밋

`글 관리 · 임시글 보관함`에서는:

- 공개·비공개·임시글 목록 조회와 제목 검색
- 선택 글 수정, 임시글 이어 쓰기, 공개 범위 전환
- 현재 글 또는 보관된 임시글 삭제

본문 입력창에 이미지를 붙여넣으면:

- 미리보기용 사진과 마크다운을 커서 위치에 삽입
- 보관함 저장 또는 발행 시 해당 공개 범위의 `assets/photos/` 경로에 업로드

#### 1) 작성 페이지 열기

- 로컬: `http://127.0.0.1:4001/my-diary/write/`
- 배포 후: `https://day-fly.github.io/my-diary/write/`

#### 2) OAuth 로그인 방식 (토큰 입력 없음)

`oauth-proxy` 폴더의 Worker를 먼저 배포해야 합니다.

- 가이드: `oauth-proxy/README.md`
- 필요한 값:
  - OAuth Client ID (GitHub OAuth App)
  - OAuth Proxy URL (Cloudflare Worker 배포 URL)

`/write` 페이지에서 두 값을 입력하고 `GitHub로 로그인` 버튼을 누르면
토큰이 자동으로 연결됩니다.

배포 명령 예시:

```bash
cd oauth-proxy
npx wrangler secret put GITHUB_CLIENT_SECRET
npx wrangler deploy
```

#### 3) 기존 발행용 토큰으로 로그인

GitHub에서 Fine-grained personal access token을 만들고 아래 권한을 주세요.

- Repository access: 이 저장소 선택
- Repository permissions: `Contents` → `Read and write`

#### 4) 연결 정보 입력

- 작성자 계정과 저장소는 `_config.yml`의 `writer.owner`, `writer.repo`, `writer.branch`로 고정됩니다.
- `/write/`의 **GitHub 로그인 키**에 발행용 토큰을 입력하고 **로그인**을 누릅니다.
- OAuth 연결을 쓰는 경우 **GitHub 간편 로그인 설정**을 펼쳐 기존 Client ID와 Proxy URL을 입력합니다.

토큰 저장 체크를 켜면 현재 브라우저에만 저장됩니다.

### 추천: 자동 생성 스크립트 사용

수작업 대신 아래 명령으로 글 뼈대를 바로 만들 수 있습니다.

```bash
./scripts/new-post.sh "일요일의 기록" "/절대경로/사진.jpg"
```

또는 대화형 입력:

```bash
./scripts/new-post.sh
```

실행하면 자동으로:

- `_posts/`에 날짜 기반 파일 생성
- (사진 입력 시) `assets/photos/`로 사진 복사
- `title`, `date`, `cover`, 본문 템플릿 자동 작성

### 수동 작성 방식

1. `_posts/` 안에 파일 생성  
   예: `_posts/2026-03-01-sunday-note.md`
2. 아래 형식으로 프론트매터 작성

```md
---
title: "일요일의 기록"

date: 2026-03-01 21:30:00 +0900
cover: /assets/photos/2026-03-01-coffee.jpg
---

오늘의 기록을 자유롭게 씁니다.

![카페 사진](/assets/photos/2026-03-01-coffee.jpg)
```

3. 사진은 `assets/photos/` 폴더에 업로드
4. Git 커밋 후 GitHub에 푸시

## GitHub Pages 배포

이 저장소에는 `.github/workflows/pages.yml`이 포함되어 있어서,  
`main` 브랜치에 푸시하면 Pages가 자동 배포됩니다.

### GitHub에서 1회 설정

1. Repository `Settings` → `Pages`
2. `Build and deployment` 에서 `Source` 를 `GitHub Actions` 로 선택

이후 푸시할 때마다 자동 배포됩니다.

## 비공개 글

작성 화면의 **공개 범위 → 비공개**를 고르면 `day-fly/my-diary-private`의 `main` 브랜치에 저장합니다. 비공개 저장소에는 GitHub Pages를 연결하지 않습니다. 공개 사이트의 목록, 검색, 추천 글, 본문과 배포 파일에는 비공개 원문을 포함하지 않습니다. 작성자 로그인 후 **글 관리 → 목록 새로고침**에서 공개·비공개 글을 함께 불러오고 수정하거나 다시 공개할 수 있습니다.

- 현재 GitHub 로그인 키가 두 저장소에 접근할 수 있어야 합니다. Fine-grained token은 선택한 저장소에 `my-diary`와 `my-diary-private`를 지정하고 Contents 읽기·쓰기를 허용해야 합니다. 기존 OAuth 간편 로그인은 `public_repo` 범위를 유지하므로, 비공개 글에는 해당 저장소 접근이 가능한 로그인 키를 사용합니다. 접근 권한이 없거나 저장소가 공개 상태이면 저장을 중단하며 공개 저장소로 대신 저장하지 않습니다.
- 새 비공개 사진도 비공개 저장소에 저장하며, 미리보기는 인증된 GitHub API를 통해 받은 사진을 현재 화면에서만 표시합니다. 붙여넣은 사진은 선택한 공개 범위를 확정하고 저장할 때까지 브라우저 메모리에만 보관합니다.
- 작성 중인 비공개 글의 자동 임시저장은 현재 탭의 세션에 보관하며 로그아웃 시 삭제합니다. **보관함 저장**을 누르면 사진과 함께 비공개 저장소에 남아 다른 기기에서도 이어 쓸 수 있습니다. 이 보관함은 발행한 비공개 글과 별도로 관리됩니다.
- 공개 글의 비공개 전환은 먼저 비공개 사본을 저장하고 원래 버전이 바뀌지 않았는지 확인한 뒤 공개 원본을 내립니다. 중간에 실패하면 현재 공개 여부를 안내하고 같은 작업을 재시도할 수 있습니다. 사이트에서 사라지는 데는 배포 시간이 필요합니다.
- **과거 공개를 되돌리는 기능은 아닙니다.** 이미 공개한 글의 Git 기록·검색 캐시·복사본과 사진의 기존 공개 주소는 남을 수 있습니다. 기존 사진은 비공개 사본으로 복사하지만 다른 글에서도 쓰일 수 있는 공개 원본을 자동 삭제하지 않습니다. 처음부터 비공개로 저장한 새 글과 새 사진은 공개 저장소에 올리지 않습니다. 외부 사진 주소는 원래 서비스의 공개 범위를 따릅니다.
